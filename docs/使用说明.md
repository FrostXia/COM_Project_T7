# Project 7 仿真与交互环境使用说明

## 1. 这套程序负责什么

本程序实现路径输入、路径处理与检查、仿真管理、机器人运动、模拟测量、状态估计接口、控制器接口和结果展示。

两种路径来源共用一个仿真环境：

1. **预设路径**：直线、圆、螺旋。
2. **手绘路径**：鼠标绘制一条连续曲线，或导入两列 XY 数值 CSV。

同时保留两种参考模式：

- `time`：按时间查找当前及未来参考状态。
- `path`：按路径进度查找参考状态。平台演示采用局部单调投影；队友可替换为其优化进度算法。

两者与路径来源独立，例如圆也可以使用 path 模式，手绘曲线也可以转换成 time 模式。

## 2. 安装位置与启动

项目位于你指定的 `Group_project/Trajectory`。将 MATLAB 当前文件夹切换到该目录，执行：

```matlab
start_trajectory
```

启动函数会临时将项目目录加入 MATLAB 搜索路径，不调用 `savepath`，不修改 MATLAB 的永久路径设置。

程序采用 MATLAB 代码式界面，入口和界面源代码可直接编辑；它不是 `.mlapp` 二进制工程。

推荐环境：MATLAB R2025a 和 Simulink。基本界面、手绘、EKF 和演示控制器不依赖额外控制或图像工具箱。正式算法使用 `fmincon` 时另需 Optimization Toolbox。

## 3. 第一次使用：先跑直线

1. Path source 选择 **Line**。
2. 使用演示默认值：长度 12 m、速度 0.5 m/s、转向上限 1.2 rad/s、采样周期 0.1 s。
3. Reference mode 使用 **path**，Controller 使用 **demo**。
4. 点击 **Smooth / preview**。
5. 检查橙色原始曲线与蓝色处理曲线，再点击 **Validate path**，查看是否有红色超限点。
6. 点击 **Confirm processed path**。
7. 点击 **Run in Simulink**。
8. 在 Path and motion、Tracking errors、Control and timing 三个页签查看结果。
9. 点击 **Export last result** 保存数据。

以上数值是界面演示默认值，不是老师给出的物理参数，也没有被宣称为最优参数。

首次运行时会调用 `build_p7_model` 生成 `models/p7_trajectory_harness.slx`。生成脚本不会覆盖已经存在的模型。如果你手动修改模型，运行前应保存或放弃未保存修改。

## 4. 三种预设路径

| 路径 | 使用的参数 | 定义 |
|---|---|---|
| Line | Line length | 从原点沿正 x 方向延伸 |
| Circle | Radius、Turns | 从原点出发，初始切线沿正 x 方向，逆时针转动 |
| Spiral | start radius、Spiral growth、Turns | 阿基米德螺旋，半径随角度增大；起点平移到原点 |

圆的半径过小仍会检查失败。螺旋也需要检查其最急转弯位置。

路径暂按一段有限长度处理，不自动无限循环。即使圆起点与终点重合，也具有有序的弧长进度。

## 5. 手绘和导入

1. 点击 **Draw / clear**，路径来源自动变为 Freehand。
2. 在坐标区域按住鼠标左键拖动，松开结束一条曲线。
3. 再次拖动会替换原始笔画，不把多段不连续笔画自动拼接。
4. 修改 Initial smoothing samples 可调节初始平滑尺度；1 表示不做自适应去抖，但仍通过连续曲线表示输入。
5. Path spacing 控制重采样间距，单位为米。
6. 点击 **Smooth / preview**，观察橙黄色原始线和蓝色处理线。此步骤先显示预览，不直接宣布验证结果。
7. 点击 **Validate path**；确认路线形状和检查报告，再点击 **Confirm processed path**。

新增 **Max smoothing shift (m)** 参数，默认 0.20 m，表示允许的最大形状改动。平滑会从较弱的设置开始，如果转弯仍太急，则逐步增强；每个候选都必须满足偏移预算。界面会显示实际最大偏移量与有效平滑尺度。

小鼠标抖动可以被修整，但程序不会仅为了显示 PASS 就忽略真实转向限制。如果预算内找不到通过的候选，保留预算内较好的曲线并给出 FAIL；这时可以增加允许偏移量后重新预览，或重画局部过紧的弯。你仍需确认蓝色曲线是否符合原始意图。

也可使用 **Import XY CSV**，文件内容应为无表头的两列有限数值，每行 `[x,y]`，单位为米。导入后按手绘路径处理。

处理采用去除相邻重复点、等弧长输入重采样、二阶差分正则化平滑和二阶连续的三次样条。端点作为约束保留，不在平滑后突然将端点拉回；航向和曲率使用样条的一阶、二阶导数计算，避免两次差分放大抖动。

形状偏移在密集采样的同序参数位置上比较，因此不会为了降低误差而任意对应到自交处的另一段。该上限是数值检查结果，不是连续区间的严格解析误差界。

## 6. “路径检查通过”是什么意思

检查包括数据是否有效、路径是否足够长、是否存在退化切线、所需角速度是否超过限制。

对固定速度模型，参考角速度由 `omega = v0 * curvature` 得到。上下界可以在脚本配置中分别设置；界面第一版使用对称转向限制。

超限样本在图中标红；未通过时不能确认和运行。相隔较远的路径进度在空间上非常接近时，会提示需要注意交叉处的进度管理。

手绘曲线会在比最终路径表更密的采样点上检查样条曲率和形状偏移，包括插值节点之间的位置。检查仍不是连续曲线的严格可行性证明，尖角、回折和密集交叉路线应人工复核。

**路径可行、求解器成功、轨迹跟踪成功是三种不同结果。** 路径检查通过，不保证任意初始位置和航向下都能收敛。

修改参数后确认状态会失效，需要重新检查和确认。

## 7. 初始位姿与定位误差

Initial x、Initial y、Initial heading 设置仿真机器人的真实初始状态。界面角度用度，内部统一转换为弧度。

Random initial pose 根据路径范围和 Random seed 生成可重复的随机位置与航向。相同种子得到相同结果，要生成另一组初值需改变种子。

Prior x/y/angle offset 设置**估计初值相对真实初值的偏差**。仿真端据此生成一次性的估计先验 `qHat0`；随后算法只接收这个先验和测量，不接收真实初值。

跟踪初始误差是机器人相对路径的偏差；定位初始误差是估计状态相对真实状态的偏差，应分别研究。

## 8. 状态估计与噪声

真实状态仅存在于机器人模型、模拟传感器与评价日志中。正式控制器和路径参考管理只接收估计状态。

| State source | 行为 |
|---|---|
| ekf | 用上一周期执行角速度预测，再用当前测量修正 |
| deadreckoning | 只根据历史估计和执行输入预测，不使用测量修正 |
| ideal | 显式启用的理想状态反馈基线，不代表实际定位能力 |

| Measured quantities | 模拟测量 |
|---|---|
| position | 只测量 x、y；航向由模型及滤波估计 |
| pose | 测量 x、y 和带噪声的航向 |

自带 EKF 是用于平台测试的实现，正式项目可通过 `config.estimatorFcn` 接入队友估计器。初始航向极不确定时不能假定 EKF 一定收敛。

噪声默认标准差在 `src/p7_defaults.m` 中集中设置：

- `stateStd = [0.003;0.003;0.005]`：每个控制采样周期对状态增量叠加的噪声，单位为米、米、弧度。
- `measurementStd = [0.03;0.03;0.03]`：每次传感器测量的噪声标准差。
- `P0`：初始估计误差协方差。

默认只打开 measurement noise。界面可以独立开关两种噪声。改变采样周期后，不能直接把这些“每次采样的协方差”解释为相同的连续时间噪声强度。

这里的 state noise 是模型扰动；名义线速度仍固定为 v0，不允许控制器主动调节线速度。

## 9. 控制器

- **demo**：追踪前视点的简单演示控制器，用于接线、交互和仿真测试。不是 LQR、MPC 或全局收敛算法。
- **openloop**：直接执行参考角速度，用于开环对照。
- **external**：调用 `adapter/p7_external_controller.m`。未接入时会记录失败并终止，不会偷偷回退到 demo。

队友控制器可以是状态反馈、LQR 或 NMPC，均通过相同外部接口接入。第一版不伪造尚未提供的 LQR/MPC 实现。

## 10. 仿真时间、停止和终点

机器人每个 Ts 更新一次，角速度在周期内保持。被控对象使用固定输入下的精确圆弧积分；与队友文档中的欧拉预测模型分开，避免直接把预测状态作为实际状态。

- time 模式：在预设最大时长或参考终点到达时间中取较早者；预测窗口超过末端时沿末端切线延续，不冻结位置。
- path 模式：达到最大时长，或估计位姿进入终点区域且进度接近末端时结束。
- Stop test：在控制器调用之间响应；正在执行的单次长优化无法被这个按钮立即打断。
- 求解器拒绝、非有限控制输入或运行错误：记录失败及已有数据，终止该次试验。

终止是结束仿真，不是让固定速度机器人在物理世界停车。闭合路径从哪个进度开始，由默认投影或队友进度算法确定，不自动保证完整走一圈。

界面动画按照计算进度更新，不承诺与真实墙钟时间保持 1:1；控制器求解时间超过 Ts 会被统计，但离线仿真不会自动模拟通信延迟。

## 11. 结果与评价

图中区分参考路径、真实轨迹和估计轨迹。true pose 对控制算法不可见，但可用于显示与计算真实误差。

time 模式的位置误差使用同一时刻参考；path 模式在当前进度附近搜索几何参考，避免任意跳到交叉的另一段。两种模式的误差不能直接混为同一指标。

记录指标包括位置 RMSE、航向 RMSE、定位 RMSE、控制代价、饱和比例、控制器调用时间和求解失败次数。

默认 `trackingSuccess` 仅表示：正常完成或到达终点、无求解失败，且最后 2 秒位置误差始终不超过 0.3 m。这是可修改的**位置跟踪判据**，不代表完整路径覆盖，也不包含额外的航向达标要求。阈值在 `p7_defaults.m` 中修改。

结果目录包含：

- `run.mat`：完整配置、路径、测量、估计、实际状态、求解日志、状态和指标。
- `timeseries.csv`：主要时间序列。
- `summary.txt`：运行状态与主要结果。
- `trajectory.png`：通过界面导出时保存的轨迹图。

取消、失败的测试也保留结果，不应从成功率统计中直接删除。

## 12. 命令行测试

```matlab
run_p7_demo                 % Run in Simulink
run_p7_demo('matlab')       % Explicit non-Simulink verification loop
run_tests(false,false)     % Core tests only
run_tests(true,false)      % Include Simulink parity and failure tests
run_tests(true,true)       % Also create and check the UI invisibly
run_batch_trials(10)       % Ten randomized Simulink trials with demo control
```

MATLAB verification loop 仅供检查模块，不是 Simulink 仿真的替代结果。界面 Run 按钮始终请求 Simulink，不自动降级为 MATLAB 循环。

## 13. 已知边界

第一版没有障碍物规划、碰撞模型、机器人实体尺寸、摩擦模型、真实硬件或部署代码。路径检查仅针对当前运动学与转向约束。

模型使用 Level-2 MATLAB S-function 和每次运行的独立会话，仅支持 Normal simulation。暂不支持代码生成、Fast Restart、Accelerator、暂停后保存并恢复会话，以及多个同名模型并行运行。
