# 算法与仿真接口约定

## 总体分层

```text
预设路径 / 手绘路径
        ↓
去重、平滑、弧长重采样、曲率检查
        ↓
已确认路径 + 试验配置
        ↓
Simulink: 参考与控制器 → 机器人模型 → 传感器与估计器
                   ↑                  ↓
                   └──── qHat ────────┘
        ↓
真实状态、测量、估计、参考、输入和求解日志
        ↓
界面 / 指标 / MAT 与 CSV
```

应用、路径预处理与仿真代码由仿真端负责；正式控制律、优化模型、滤波策略和路径进度算法由算法端负责。

## 1. 不变的单位和约定

- 状态：`[x;y;theta]`，3×1 double。
- 单位：m、s、rad、m/s、rad/s。
- 坐标：x 向右、y 向上、逆时针为正。
- 控制器输出实际物理角速度 omega，不能直接输出 `omega - omegaReference`。
- 线速度 v0 为单次试验固定参数。
- 内部航向允许超过 ±pi；测量创新和报告误差进行周期处理。
- 算法只能读取估计状态、参考和公开配置，不能从 workspace、registry 或其他旁路读取 qTrue。

## 2. 控制器接口

```matlab
[omega, memory, info] = controllerStep(qHat, ref, config, memory)
```

### 输入

| 名称 | 维度／形式 | 含义 |
|---|---|---|
| qHat | 3×1 | 当前采样时刻经过修正的估计位姿 |
| ref.mode | 'time' / 'path' | 参考模式 |
| ref.q | 3×(N+1) | 当前和未来 N 步参考位姿 |
| ref.w | N×1 | N 个区间的参考物理角速度 |
| ref.s | 标量 | 平台参考管理提供的当前进度 |
| ref.t | 标量 | 当前仿真时间 |
| ref.path | 结构体 | 完整路径几何，供算法自主维护进度 |
| ref.target | 3×1 | 演示控制器前视目标，正式算法可忽略 |
| config | 结构体 | 统一参数，可加入 config.algorithm 存放私有权重 |
| memory | 任意可维护数据 | 首次为空，可保存 warm start 和优化进度 |

算法获得的 config 不含 `q0` 和 `initialEstimateOffset`，只包含一次性估计先验 `qHat0`。估计先验是仿真初始化条件，不能被当成每步真实状态使用。

### 输出

| 名称 | 要求 |
|---|---|
| omega | 有限实数标量，单位 rad/s |
| memory | 下一次调用时原样传回；新试验自动重置 |
| info.ok | 必须返回逻辑标量；false 表示拒绝执行、记录失败并停止 |
| info.message | 建议返回可读诊断信息 |
| info.predictedQ | 可选的预测轨迹；当前会话保留最后一次值，第一版界面尚不绘制 |
| info.constraintResidual | 可选的标量约束残差，默认 NaN 表示未提供 |

仿真端会对有限控制输入再次限幅，同时保存请求值和执行值。正式 MPC 应在自身问题中包含相同限幅，不能依赖外部限幅掩盖优化约束违规。

外部控制器必须自行完成其约束残差、exitflag 和候选解接受检查。平台无法仅凭一个角速度重新检查优化状态序列。

### 接入步骤

1. 将队友函数放入 `adapters` 或另一个明确加入路径的算法子目录。
2. 修改 `adapter/p7_external_controller.m` 的函数体。
3. 将 `config` 映射为队友的参数结构 p，例如 `p.v0=config.v0; p.Ts=config.Ts; p.N=config.N;`。
4. 使用 `ref.q/ref.w`，将当前 `qHat` 传给约束函数。
5. 求解通过后输出第一项物理角速度，保存移位初猜到 memory。
6. 界面选择 external 测试。接口未完成时返回失败，不自动切换演示算法。

## 3. 估计器接口

```matlab
[qHat, memory] = estimatorStep(measurement, previousOmega, config, memory)
```

通过脚本设置：

```matlab
config.estimatorMode = 'external';
config.estimatorFcn = @myEstimatorStep;
```

`measurement` 为 2×1 的位置测量或 3×1 的位姿测量。首次调用没有上一周期预测，只初始化并按需要测量修正；后续先用上一周期执行输入预测，再使用当前测量修正。

`config.qHat0` 是估计初值；`config.P0` 是初始协方差。接口不包含真实位姿。界面第一版提供 ekf、deadreckoning 和 ideal；external 估计器通过脚本运行配置。

## 4. 路径数据

`path` 字段：

- `s`：M×1 严格递增弧长表，起点为 0。
- `xy`：M×2 位置表。
- `theta`：M×1 连续切线角。
- `kappa`：M×1 有符号曲率。
- `length`：总弧长。
- `raw`：原始输入点，保留以便解释平滑造成的变化。
- `kind`：line、circle、spiral、freehand。

`p7_path_query(path,s,config)` 提供查询。超出末端时沿末端切线延伸，主要用于提供完整预测窗口，不代表机器人可以停车。

时间参考的形状与速度在连续意义上相容，但不保证精确满足队友的欧拉离散模型。必要时检查文档中的模型残差，减小 Ts 或调整参考离散方法。

## 5. 路径进度扩展

默认 `p7_reference` 首次从估计位置寻找最近路径点，之后在局部前向窗口内更新非递减进度。这是演示策略，不是文档第 13 页中同时优化 s 和 nu 的 NMPC。

正式路径跟随算法可以：

1. 直接使用 `ref.path`，在 controller memory 中维护自己的 s/nu；并提供匹配的参考管理。
2. 设置 `config.referenceFcn` 替换整个参考生成函数：

```matlab
[ref, memory] = referenceStep(qHat, time, path, config, memory)
```

必须保证控制器、日志参考、终点判定使用一致的进度含义。不要只在控制器内部切换进度，却继续将平台另一套进度用于评价。需要共享算法进度时，应显式扩展接口后再比较结果。

参考管理在控制器之前执行；如需要使用上一次优化得到的进度，需明确定义跨周期的传递方式。第一版没有暗中实现这一额外共享状态。

## 6. Simulink 内部

模型由 `build_p7_model.m` 创建，包含三个主要 Level-2 MATLAB S-function：

| 模块 | 作用 |
|---|---|
| Robot plant | 保存真实位姿；用执行角速度独立推进运动，并加入 state noise |
| Sensor and estimator | 根据真实位姿生成测量，执行状态估计，仅向控制器输出 qHat |
| Reference and controller | 生成参考，调用选定控制器，检查接口结果、记录诊断 |

Previous applied omega 是显式一拍延迟，用于下一时刻的状态预测。Robot plant 无直接馈通，因此不会通过测量—控制形成代数环。

每次运行创建独立会话、随机数流、初始估计与算法 memory。每个时间索引缓存一次估计和控制结果，防止 Simulink 重复求值时再次采样噪声或重复运行优化器。

模型文件本身不包含登录信息、全局凭据或外部服务调用。算法的 .m 文件运行于 MATLAB Normal simulation 环境；第一版不涉及嵌入式部署。

## 7. 谁负责下一步

- 仿真端：界面、路径处理、模型连接、场景与噪声生成、数据保存、显示与一致性测试。
- 算法端：正式 LQR/MPC、估计器选择与设计、权重、约束、求解接受条件、路径进度优化。
- 共同：实际 v0、Ts、转向能力、传感器假设、评价指标、复杂路径和公平对比条件。
